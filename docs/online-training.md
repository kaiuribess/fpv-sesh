# Online learning and flight maps

FPV Sesh uses an optional **existing internet-pretrained scene model**, Places365 ResNet18, alongside measured image motion. It has not trained a new FPV trick classifier. Places365-Standard contains approximately 1.8 million scene images across 365 categories. The authors publish the checkpoint and inference recipe in the [official Places365 repository](https://github.com/CSAILVision/places365).

Run `setup-ai.ps1` to prepare the isolated Torch runtime, then `setup-vision.ps1` to install and verify the 45.5 MB scene checkpoint. `setup-vision.ps1 -CheckOnly` verifies existing files and performs one inference without downloading. The scene model works on CUDA when available and CPU otherwise. A fresh clone with no optional model still produces motion maps and clearly reports that online scene inference is unavailable. No footage is uploaded, no API key is needed, and no paid service is used.

## What is actually inferred

One frame per second of each complete analysis proxy is processed with the author's 256-square resize, 224-center crop, RGB ImageNet normalization, and checkpoint-compatible ResNet18. Predictions retain top-five class scores, but the editor uses broader groups such as park/open grass, woodland, sky, and built surroundings. Group softmax mass below 0.35 yields an uncertain scene. These scores are **not calibrated probabilities of correctness**. The implementation follows the official [inference example](https://github.com/CSAILVision/places365/blob/master/run_placesCNN_basic.py) and [torchvision architecture](https://github.com/pytorch/vision/blob/v0.24.1/torchvision/models/resnet.py).

Flight maps show three-second motion windows, scene context, and separately attributed user-confirmed intervals. Rotation bursts, moving lines, close-pass/weave estimates, and low-motion periods are measurements and heuristics. A close pass with vegetation context does not prove a tree gap, and image rotation cannot distinguish a named flip, roll, or tracking orbit reliably. Scene context never overrides landing guards, changes source boundaries, or changes candidate ranking automatically.

The first local validation processed 569 sampled frames spanning the three supplied flights in 7.49 seconds on an RTX 4060 Ti. Eight selected source frames were visually checked: seven broad grass/sky contexts matched their visible surroundings; the lens-in-grass frame abstained. This is a small selected spot check, **not a held-out accuracy benchmark**. Fine classes often incorrectly called the park a golf course or baseball stadium. A landed frame still contained mostly sky, demonstrating why scene recognition cannot decide whether the drone is airborne. Local evidence is in `logs/online-scene-validation.json` and `logs/online-scene-contact-sheet.jpg`, excluded from Git.

## Local corrections and validation

Confirmed labels save source SHA256 identities, exact intervals, and eight normalized motion features under `cache/learning`. Each input label must carry its full `source_identity` SHA256 from the moment it was confirmed. Unbound legacy labels and labels whose source bytes changed are skipped with a visible request to re-confirm; merely reusing a file path never transfers a confirmation. A label needs at least three confirmed examples across two distinct source identities before nearest-neighbor estimates are enabled. Distant or disagreeing neighbors abstain. The report measures leave-one-flight-out accuracy including abstentions: all examples from the held-out source are removed from its neighbors. With few examples or a single enabled class, this is only a diagnostic, not evidence of general FPV recognition. Confirmed labels, local example matches, motion heuristics, and online scene estimates retain separate methods in the map.

Completed scene caches are keyed by original source identity, proxy SHA256, model SHA256, inference implementation hashes, and duration. Broken or stale records are recomputed. Pause and cancel are checked between decoded proxy frames; completed source maps survive cancellation. The checkpoint is loaded using `weights_only=True`, and all model/category/license assets are checked against the committed manifest. Full licensing, attribution, and the limitation of the initial official HTTP download are documented in [MODEL-LICENSE.md](../models/places365/MODEL-LICENSE.md).

## Datasets assessed before choosing this approach

- [Imageomics drone-maneuver-clips](https://huggingface.co/datasets/imageomics/drone-maneuver-clips) is CC BY 4.0, but its action labels replay a hypothetical animal-tracking controller, rather than describe the drone's actually flown camera motion. It was rejected for FPV trick training; nothing was downloaded.
- [UZH-FPV](https://fpv.ifi.uzh.ch/) provides real FPV racing images, IMU measurements, and trajectories under a noncommercial share-alike license. It lacks the required freestyle trick labels; nothing was downloaded.
- [Deep Drone Acrobatics](https://github.com/uzh-rpg/deep_drone_acrobatics) offers MIT-licensed acrobatic trajectory/control code, not a pretrained video trick recognizer. It was not presented as learned video recognition.
- [CameraBench](https://github.com/sy77777en/CameraBench) and its [CC BY 4.0 data card](https://huggingface.co/datasets/syCen/CameraBench) describe actual camera-motion annotations. This is a possible future benchmark for pan/tilt/roll understanding, with a substantial domain gap to FPV freestyle. It has not been trained on or downloaded here.

The original Places365 weight license is CC BY with no version specified by upstream. Code notices (MIT and BSD-3-Clause) are retained separately. Weights, training examples, original videos, and inference caches are excluded from the repository.
